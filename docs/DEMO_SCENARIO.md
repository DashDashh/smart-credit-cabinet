# Демо-сценарии

8 тестовых клиентов. Каждый сценарий — 30–60 секунд. Полное демо — 5–7 минут.

## Перед началом

1. Запустить приложение: docker compose up --build.
2. Открыть фронт: http://localhost:3000.
3. Проверить decision: curl http://localhost:8000/health → {"status":"ok","ml_available":true}.
4. Переключиться на роль «Клиент».

Схема БД и тестовые данные применяются автоматически при первом запуске (`01-schema.sql`, `02-test-data.sql` в `/docker-entrypoint-initdb.d/`).

## Обозначения

- Клиент — личный кабинет предпринимателя.
- Сотрудник — личный кабинет банковского работника (переключатель ролей).
- Система — Java-оркестратор + decision.

## 1. Идеальный клиент → approved

Клиент: ООО «ТехноСофт» (IT, 3 года, выручка 18 млн, без просрочек).

Что сделать:

1. Клиент → выбрать «ООО ТехноСофт».
2. Нажать «Подать заявку» → выбрать «Оборотный кредит, 2 000 000 ₽, 12 мес.».
3. Проверить предзаполненные данные → «Отправить».
4. Перейти в лк Сотрудника в "Заявки" и посмотреть на Решение (далее так делать при всех следующих сценариях). Скоринг должен быть 100 из 100
5. Одобрить заявку и вернуться в лк клиента

Что должно быть:

| Поле | Значение |
|---|---|
| decision | approved |
| score | ≈ 99.8 |
| risk_level | low |
| rate | 17.5 |
| conditions | null |
| model_version | logreg-v1 |
| next_step | client_accept_terms |

Факторы (топ-3):
- business_status=active — снижает риск;
- delinquencies_12m=0 — снижает риск;
- debt_load=0.07 — снижает риск.

Действие клиента: «Принять условия» → «Подписать» → статус DISBURSED.

## 2. Средний риск → approved_with_conditions

Клиент: ИП Иванов (кафе, 9 мес., 2 просрочки, налоговая задолженность).

Что сделать:

1. Клиент → выбрать «ИП Иванов (кафе)».
2. Нажать «Подать заявку» → «Оборотный кредит, 3 000 000 ₽, 12 мес.».
3. «Отправить».

Что должно быть:

| Поле | Значение |
|---|---|
| decision | approved_with_conditions |
| score | 45–65 (≈ 58) |
| risk_level | medium |
| conditions.approved_amount | 2 100 000 (70% от 3 млн) |
| conditions.term_months | 12 |
| conditions.rate | ≈ 18.6 (base 17.5 + premium) |
| rate | ≈ 18.6 |
| model_version | logreg-v1 |
| next_step | client_accept_conditions |

Что видит клиент: «Одобрено с условиями: сумма 2 100 000 ₽, срок 12 мес., ставка 18.6%».

Действие клиента: «Принять условия» → «Подписать» → DISBURSED. Или «Отклонить» → заявка закрывается.

Что показывает: банк не отказывает сразу, а предлагает альтернативу (меньше сумма, выше ставка).

## 3. Высокий риск → rejected (ML)

Клиент: ИП Петров (стройка, 8 мес., 3 просрочки, убыток, высокая нагрузка).

Что сделать:

1. Клиент → выбрать «ИП Петров (стройка)».
2. Нажать «Подать заявку» → «Оборотный кредит, 4 000 000 ₽, 12 мес.».
3. «Отправить».

Что должно быть:

| Поле | Значение |
|---|---|
| decision | rejected |
| score | < 45 (≈ 30–40) |
| risk_level | high |
| rate | null |
| conditions | null |
| model_version | logreg-v1 |
| next_step | notify_client_rejection |

Что видит клиент: «Отказ. Причина: высокий риск (score 35 из 100)». Факторы:
- 3 просрочки за 12 мес.;
- долговая нагрузка 0.93;
- отрицательная прибыль;
- налоговая задолженность.

Что показывает: ML объясняет отказ — клиент видит, что именно плохо.

## 5. Hard_block: сумма > лимита продукта → rejected

Клиент: ООО «ПромТех» (производство, 4 года, выручка 60 млн — хороший профиль).

Что сделать:

1. Клиент → выбрать «ООО ПромТех».
2. Нажать «Подать заявку» → «Инвестиционный кредит, 50 000 000 ₽, 36 мес.».
3. «Отправить».

Что должно быть:

| Поле | Значение |
|---|---|
| decision | rejected |
|score | 0.0 |
| risk_level | high |
| rate | null |
| model_version | `policy-v1` |
| next_step | notify_client_rejection |

Факторы:
- amount_above_product_limit (`impact = -100`, value = 50000000, description = «Сумма 50 000 000 ₽ превышает лимит продукта (30 000 000 ₽). Уменьшите сумму или выберите другой продукт»).

Что показывает: продуктовые лимиты — бизнес-правило, не ML. Даже хороший клиент не получит сумму выше лимита.

## 6. Неполные данные → needs_info

Клиент: ИП Кузнецов (не указана месячная выручка, не указана сумма долга).

Что сделать:

1. Клиент → выбрать «ИП Кузнецов (неполные данные)».
2. Нажать «Подать заявку» → «Оборотный кредит, 1 000 000 ₽, 12 мес.».
3. «Отправить».

Что должно быть:

| Поле | Значение |
|---|---|
| decision | needs_info |
| score | 0.0 |
| risk_level | medium |
| rate | null |
| model_version | `data-check-v1` |
| next_step | bank_request_info |

Факторы (с `description`):
- missing_revenue_monthly — «Укажите месячную выручку — без неё невозможна оценка долговой нагрузки»;
- delinquencies_without_debt — «У вас 2 просрочек, но не указана сумма обязательств. Уточните сумму или приложите кредитную историю».

Что видит клиент: «Нужна доработка. Заполните: месячная выручка, сумма обязательств».

Действие клиента: заполнить поля → отправить снова → теперь идёт скоринг.

Что показывает: needs_info — результат data-check, не порог score. ML не вызывается, клиент получает конкретные инструкции.
